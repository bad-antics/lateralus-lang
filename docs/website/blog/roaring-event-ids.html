Which events still need a replay?

A collector receives a batch twice after a reconnect. Some IDs in the second batch are genuinely new. We want to print each new ID once, in arrival order, and count the records we can skip. An integer set remembers what arrived. A separate list keeps the order in which we discovered missing events.

Start at a container boundary

The Roaring module at the tested revision splits an unsigned 32-bit ID into two 16-bit parts. For 65,535 the pair is (0, 65,535). Increment the ID once and the pair becomes (1, 0). The value 131,072 is (2, 0). Those last two IDs share a low word, so the example will catch any check that accidentally ignores the high word.

let received = new_bitmap()
let first_batch = [65536, 42, 65535, 65536]
for id in first_batch {
    received = add(received, id)
}

// Preserve the order of the incoming batch when reporting missing events.
let second_batch = [65535, 65537, 42, 131072, 65536, 65537]
let missing = []
let already_seen = 0
for id in second_batch {
    if has(received, id) {
        already_seen = already_seen + 1
    } else {
        missing = missing + [id]
        received = add(received, id)
    }
}
print(missing)
print(already_seen)

Check membership before adding each ID from the second batch. Recording 65,537 on its first appearance makes its second appearance a replay. If you waited until the end of the batch to update the bitmap, the output would request 65,537 twice.

Run the fixed vector

From the repository root, run the example and check its output with Python 3.10 or newer:

python tests/test_roaring_event_ids.py -v

The test joins the original module and examples/roaring_event_ids.ltl in a temporary compilation unit, runs the project's lateralus_lang run command, and compares both output lines. It works from a checkout without a global Lateralus installation.

[65537, 131072]
4

The skipped records, in order, are 65,535, 42, 65,536, and the second 65,537. Together with the two replay requests, that accounts for all six incoming records. These small batches exercise sparse containers. A single container switches to bitmap storage only after its own count exceeds 4,096 distinct values.
